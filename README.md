# 몬길 몬링 매니저

독립적인 정적 GitHub Pages 사이트입니다. DB·로그인·빌드 설치 없이 동작합니다.

- `index.html`: 품종 효과 / 링크체인 통합 도감. 196종, 품종 1~5등급, 링크체인 레벨별 수치.
- `recipes/index.html`: 기존 조합식 검색기. 성공률 100%, 하위 재료 / 상위 조합 탐색 유지.
- 도감 분류: 발동 조건을 제외한 효과 속성 기준. 공용, 땅/바람/번개/불/얼음, 기타(물리/물/암흑). 몬링 자체의 속성으로 분류하지 않습니다.
- 목록은 처음 40개만 표시하고 더 보기로 확장합니다. 아이콘은 지연 로딩하며 각 페이지의 데이터는 따로 로드합니다.
- 링크체인의 추가 효과는 표에 표시하고 전체 행동 설명은 펼쳐볼 수 있습니다.
- GA4는 기존 방문 통계만 유지하며 검색어·선택 설정을 수집하지 않습니다. 개발 서버에서는 비활성입니다.

## 배포

1. GitHub에 `MonGilMonlingManager` 저장소를 생성하고 이 폴더 내용 전체를 저장소 루트에 올립니다. 폴더 자체를 한 단계 감싸서 올리지 않습니다.
2. Settings → Pages에서 main 브랜치 / 루트(`/`)를 게시합니다.
3. 예상 주소: https://southsilverg.github.io/MonGilMonlingManager/
4. 새 도감과 조합식이 열리는 것을 확인한 뒤 파티 매니저 변경을 배포합니다. 파티 매니저의 왼쪽 메뉴에서 몬링 매니저로 이동합니다. 기존 파티 저장소의 recipes 폴더는 제거했습니다.

파티 매니저 주소는 `index.html`, `recipes/index.html`의 `data-party-link`에 있습니다. 저장소 이름이 달라지면 파티 매니저 쪽 메뉴의 `data-monling-link` 주소도 함께 수정해야 합니다. 별도 개인 도메인은 필요 없습니다.

파티 매니저의 `assets` 폴더는 에디터에서도 사용하는 이미지이므로 삭제하지 마세요. 파티 매니저의 `recipes` 폴더는 전체 삭제 대상으로 커밋해야 합니다. 기존 검색기 주소는 더 이상 제공하지 않습니다.

## 로컬 확인 / 갱신

파티 매니저는 8765, 이 폴더는 8766 포트로 각각 정적 서버를 실행하면 두 사이트 이동도 로컬에서 확인할 수 있습니다.

`python tools/build-catalog.py`는 상위 폴더의 STARDIVE_Extract/data 및 원본 테이블과 파티 매니저의 에셋을 이용해 도감 데이터와 필요한 이미지만 생성합니다. `source-monsters.json`은 파티 에디터의 등록 목록 스냅샷입니다. 원본 클라이언트 전체나 원본 테이블은 이 저장소에 포함하지 않습니다.

검증: 저장소 루트에서 `node tests/catalog.test.cjs`.

링크체인 필터는 공격의 피해 속성이 아니라 부여 효과 기준입니다. 속성 저항 감소는 해당 속성, 방어력 감소·받는 약점 속성 피해 증가·제어 효과 등은 공용으로 분류합니다. 여러 효과를 부여하면 복수 분류에 포함되고, 별도 부여 효과가 없으면 효과 없음으로 표시합니다. 피해량은 전체 효과 펼침 안에 유지합니다.

조합식에서 몬링을 선택하면 이름 오른쪽에 링크체인 부여 효과와 품종 효과를 표시합니다. 링크체인 레벨/품종 등급을 변경할 수 있으며, 요약 전용 데이터(recipes/effects-data.js)는 선택 후 한 번만 내려받습니다. 모바일에서는 이름 아래로 배치합니다.
